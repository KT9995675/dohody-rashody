# Доходы–расходы — спецификация

Простое веб-приложение на Google Apps Script (GAS) для учёта личных финансов.  
Данные хранятся в Google Таблице. Код пишем только по команде «Пишем».

## 1. Цель и границы

### 1.1. Цель

Вести личный учёт доходов и расходов: быстро добавлять записи (в том числе голосом), видеть баланс и список с фильтром по дате.

### 1.2. В первой версии нет

- Нескольких счетов/кошельков  
- Начального баланса  
- Категорий доходов  
- Мультивалютности  
- Совместного доступа  
- Статистики/графиков (кроме баланса и списка)  
- Объединения категорий

### 2.1. Веб-приложение

- HtmlService, деплой Web App **Anyone** (для Mobile API); UI `doGet` — только владелец.  
- Баланс, фильтр, список, CRUD, категории, разбор **текстовой** фразы через Gemini.  
- Голос в iframe GAS не используется (микрофон недоступен).

### 2.2. Android (v1.1.0)

- Один главный экран: список + composer внизу (поле «Заметка», отправить, микрофон).  
- Подтверждение и правка — экран **Запись** (`EditTxActivity`, режим create/edit).  
- Категории — в **Настройках** (не отдельная вкладка).  
- Связь: `MobileApi.gs` (`doPost` + `doGet?token=&action=ping`). POST → 302 → GET на redirect (см. `GasClient.kt`).

### 2.3. Mobile API (`MobileApi.gs`)

Действия в JSON `action` (тело `text/plain`, token в query или body):

| action | Назначение |
|--------|------------|
| `ping` | Проверка связи (также GET) |
| `parseText` / `parseAudio` | Разбор заметки |
| `create` / `update` / `delete` | CRUD записей |
| `dashboard` | Баланс + список за период |
| `getTransaction` | Одна запись |
| `listCategories` / `addCategory` / `renameCategory` / `deleteCategory` / `categoryUsage` | Категории |

## 3. Модель данных

### 3.1. Лист `Transactions`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | string | Уникальный id записи |
| `createdAt` | datetime | Фактическое время создания (не меняем при правке даты операции) |
| `date` | date/datetime | Дата операции: при создании = сейчас; редактируется вручную |
| `type` | `income` \| `expense` | Доход или расход |
| `amount` | number | Сумма в рублях (> 0) |
| `category` | string \| empty | Только для расхода; у дохода пусто |
| `comment` | string | Комментарий из заметки / ручной ввод |
| `source` | `manual` \| `web_voice` \| `android_voice` \| `android_text` | Откуда создана |
| `rawText` | string | Исходный текст заметки (если был) |

### 3.2. Лист `Categories`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | string | Уникальный id |
| `name` | string | Название (уникально без учёта регистра) |
| `createdAt` | datetime | Когда добавлена |

Категории только для расходов. Список пополняется при подтверждении новой категории при создании записи и при ручном добавлении в приложении.

### 3.3. Баланс

```
balance = sum(amount where type=income) - sum(amount where type=expense)
```

Считается по всем записям (фильтр дат на баланс в v1 не влияет — баланс всегда общий).  
Отображаемый список и суммы «за период» (если понадобятся в UI) — по фильтру; **общий баланс** на экране — без фильтра.

*Уточнение при реализации UI:* на экране всегда показывать общий баланс; опционально рядом — сумма доходов/расходов за выбранный период (не обязательно в v1, см. §7).

## 4. Пользовательские сценарии

### 4.1. Ручное создание записи (веб)

1. Пользователь заполняет: тип, сумма, комментарий; для расхода — категория (выбор из списка или «новая»).  
2. Если новая категория — подтверждает название (или выбирает существующую).  
3. Подтверждает сохранение → строка в `Transactions`; при новой категории — строка в `Categories`.  
4. `date` и `createdAt` = момент сохранения; `source` = `manual`.

### 4.2. Голос и текст (Android)

1. Пользователь вводит текст в composer **или** нажимает микрофон (сразу запись; повторное нажатие — стоп).  
2. `parseText` / `parseAudio` → Gemini → экран **Подтверждение** (тот же UI, что редактирование).  
3. Категория — выпадающий список + возможность новой (с подтверждением).  
4. **Записать** → `create`; `source` = `android_text` / `android_voice`.

### 4.3. Ручное создание (веб)

См. §4.1 (без изменений по смыслу).

### 4.4. Редактирование записи

- Можно изменить: дату операции, тип, сумму, категорию (для расхода), комментарий.  
- `createdAt` и `id` не меняются.  
- Смена категории на новую — с тем же подтверждением, что при создании.

### 4.5. Удаление записи

- Подтверждение в UI → удаление строки из `Transactions`.  
- Категории автоматически не удаляются.

### 4.6. Фильтр списка по дате

- Произвольный период: дата «с» и «по».  
- Пресеты: сегодня; текущая неделя; текущий месяц; всё время.  
- Фильтр влияет на список записей (и при наличии — на суммы за период), не на общий баланс.

### 4.7. Управление категориями

- **Добавить** — имя; проверка уникальности.  
- **Переименовать** — обновляет справочник и все записи с старым именем.  
- **Удалить** — если есть расходы с этой категорией, спросить категорию-замену → обновить записи → удалить из справочника. Если записей нет — удалить сразу (с подтверждением).

### 4.8. Автопоявление категории

- Разбор предложил категорию, которой нет в `Categories` → не писать в справочник до явного подтверждения пользователя (веб или Алиса).  
- После подтверждения — добавить в `Categories` и использовать в записи.  
- Отказ — пользователь выбирает существующую (или вводит другое имя с новым подтверждением).

## 6. Безопасность и деплой

- Gemini API key — только Script Properties (`GEMINI_API_KEY`).  
- Секреты не в APK и не в клиентском HTML.

## 9. История решений (обсуждение)

- UI: веб-приложение на GAS (не сайдбар таблицы).

- CRUD записей: создание, редактирование, удаление.  
- Дата: при создании = сейчас; при редактировании можно менять.  
- Баланс: сумма доходов − сумма расходов.  
- Сохранение только после подтверждения.  
- Фильтр: период + пресеты.  
- Таблица: container-bound.  
- Категории: добавить, переименовать, удалить; при удалении — спросить замену для старых записей.
